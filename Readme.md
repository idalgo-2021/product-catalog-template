# Продуктовый каталог

Это boilerplate-проект для быстрого старта новых сервисов, экспериментов и т.п.


## Требования к проекту

1. Создать простую витрину с каталогом товаров, без складов, резервов, складских операций и т.п. 
2. Сведения о товарах должны содержать набор фотографий, текстовое описание и другие атрибуты. 
3. Реализовать упрощенный вариант JWT-based авторизации.
4. Реализовать возможность создания и изменения пользователями заказов товаров. 
5. Проект должен реализовывать лишь базовый функционал клиент-серверного взаимодействия(предполагаемые клиенты - WEB и Mobile). 


## Явные ограничения и особенности

* Товары это простой плоский список(с ценой и остальными атрибутами).
* Товары заказа хранятся в виде атрибута заказа как массив строк JSONB-объект. 
* В строках заказов нет наименований товаров, а только их ИД, количество, цена.
* Картинки в БД не хранятся, хранятся только ссылки на них. 
* В AUTH-модуле нет логаута, нет отзывов токенов, смены пароля, почты и т.п.
* В middleware нет валидации  email, пароля, идентификаторов и т.п., но есть валидация типа токена.
* Специальных пакетов/схем валидации не используется.
* Нет системы ролей.
* Нет админки(и соответствующих api-ручек).
* Нет кэша(товаров, заказов, картинок).
* CORS настроен с AllowedOrigins: ["*"]
* Нет rate limiting и прочих защитных механизмов, таймаутов и ретраев запросов, сбора метрик и т.п.
* Нет ограничений на размер "табличной части" заказа(т.е. на количество строк в заказе).
* Нет компрессии ответов сервера.
* Нет тестов (unit/integration).
* Хэширование паролей без соли

*Данные товаров и картинки для seed-скрипта взяты из https://github.com/octaprice/ecommerce-product-dataset*


## Настройка проекта

1. Скачайте проект.
2. Настройте переменные окружения в `.env`. 
3. Выполните в каталоге проекта команду инициализации БД: ```make db-up```.
4. Запустите в каталоге проекта инит-скрипт структуры таблиц БД: ```go run cmd/migrate/main.go init```.
5. Запустите в каталоге проекта инит-скрипт структуры таблиц БД: ```scripts/seed_products.sql```.


## Структура проекта

Проект организован по принципам Слоистой архитектуры, что упрощает разделение ответственности, тестируемость и масштабируемость.

```bash
product-catalog-backend/
├── cmd/                          # Точки входа в приложение
│   ├── server/                   # Основной HTTP-сервер
│   │   └── main.go
│   └── migrate/                  # Утилита для миграций базы данных
│       └── main.go
│
├── internal/                     # Основной код проекта (не импортируется извне)
│   ├── domain/                   # Бизнес-сущности и ошибки
│   │   ├── product.go
│   │   ├── order.go
│   │   ├── user.go
│   │   └── errors.go
│   │
│   ├── handler/                  # HTTP-хендлеры и DTO
│   │   ├── product/
│   │   ├── order/
│   │   ├── auth/
│   │   ├── response.go
│   │   └── pagination.go
│   │
│   ├── service/                  # Бизнес-логика
│   │   ├── product_service.go
│   │   ├── order_service.go
│   │   ├── auth_service.go
│   │   └── interfaces.go
│   │
│   ├── repository/               # Работа с данными (PostgreSQL)
│   │   └── postgres/
│   │       ├── product_repo.go
│   │       ├── order_repo.go
│   │       └── user_repo.go
│   │
│   ├── middleware/               # HTTP middleware
│   │   ├── auth.go
│   │   ├── logging.go
│   │   └── recovery.go
│   │
│   ├── config/                   # Конфигурация приложения
│   ├── auth/                     # JWT и аутентификация
│   └── router/                   # Настройка маршрутов
│
├── pkg/                          # Код, который можно переиспользовать в других проектах
│   ├── db/                       # Подключение к базе данных
│   └── logger/                   # Логирование
│
├── migrations/                   # SQL-миграции базы данных
├── scripts/                      # Полезные скрипты (seed данных и т.д.)
├── docs/                         # Swagger-документация
├── _data/                        # Локальные данные (PostgreSQL volume)
│
├── docker-compose.yaml
├── Dockerfile
├── Makefile
├── go.mod
└── README.md
```

## Прочее

* Для автоматизации действий используется `Makefile`
* Swagger-документация(пакет `swaggo`) доступна в каталоге `docs` или `http://HOST:PORT/swagger/index.html`
